Source export checked on 19 October 2026 using Node.js 24.19.0.

## Completed checks

- A clean dependency installation and production Vite/PWA build.
- TypeScript validation of the application and build configuration.
- All 13 record/calculation tests in `tests/model.test.mjs` passed: manual times and unpaid breaks; daily/weekly multi-job totals; historical rate snapshots; overnight shifts; rounding; invalid entries; overlap rules; unfinished shifts; archive/delete/restore history; JSON backup validation; CSV escaping; week/month boundaries; stale edits; and ID generation where `crypto.randomUUID` is unavailable.
- Browser checks in Chrome with phone-sized frames: create two jobs with different rates; manually add and save shifts; filter by job; reload and retain records; prepare both weekly and monthly PDF files. The example day returned 8 hours at GBP 13/hour plus 4 hours at GBP 22/hour, totalling 12 hours and GBP 192 before deductions.
- Home, Reports and preferences layouts checked for horizontal overflow at narrow phone widths. Visible form inputs use 16px text. The interface uses native date/time controls, touch targets and safe-area padding.
- PDF fixtures generated using the actual app PDF generator and bundled fonts. A weekly report with 14 shifts returned 80.5 paid hours and GBP 1,324.75. A monthly report with 62 shifts returned 356.5 paid hours and GBP 5,866.75.
- All pages of these multi-page PDFs were rendered and visually inspected. Long job names and notes wrap, continuation pages retain headers, totals remain together, and every page includes creator credit and page numbers. Text extraction also checked totals and credits.
- Production manifest, install icons, service worker and the offline precache are generated by `vite-plugin-pwa`. The app shell, lazy PDF engine and PDF fonts are included in the cache.
- The ZIP contains source, assets, lockfile, instructions and reproducible calculation/PDF fixtures; it excludes dependencies, local data and generated verification files.

## Practical limits and deployment check

The Chrome checks used a desktop browser with phone-sized frames, rather than physical iOS/Android devices. Actual Home Screen installation, mobile native sharing and offline relaunch on physical phones must be checked at the final deployed HTTPS address. This source package does not provision or publish a GitHub/Vercel project.

A weekly PDF was prepared in the browser and exposed as a downloadable PDF. The cloud browser's automated download event timed out, so an automated browser-to-disk download is not claimed. The same export function successfully wrote and rendered both PDF fixtures on disk.

After deployment, use the following short acceptance check on a phone:

1. Open the HTTPS address online and add a test job and shift.
2. Install through Safari's Add to Home Screen or Chrome's Install app menu.
3. Open the installed app once online, then turn on airplane mode and relaunch it.
4. Confirm the saved shift, add another shift and prepare a PDF offline.
5. Turn airplane mode off; download/share a weekly PDF and a monthly PDF.
6. Export a JSON backup and keep a copy outside the browser.

Records are local to each browser/device/origin. This version does not offer cloud accounts or cross-device synchronisation. Pay calculations are base gross estimates, with the assumptions documented in the README.
